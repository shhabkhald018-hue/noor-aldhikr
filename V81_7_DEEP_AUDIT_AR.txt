نور الذكر V81.7 — تقرير الفحص العميق وإصلاح صفحة المالك

النتيجة:
تمت مراجعة النسخة V81.6 كاملة وإصلاح طبقة المالك والاتصال والكاش وPWA، مع عدم حذف بيانات Supabase وعدم إعادة بناء قاعدة البيانات.

المشكلات المؤكدة التي تم إصلاحها:
1) Owner Studio كان يمكن أن يُنشأ قبل تسجيل المالك، ثم يرفض تحميل البيانات بعد نجاح الدخول بسبب dataset.ready.
   الإصلاح: فصل إنشاء الواجهة عن تحميل البيانات، وإعادة loadAll فعليًا عند noor:admin-ready.

2) NOOR_OWNER_ID لم يكن يُضبط داخل مسار دخول المالك الحالي.
   الإصلاح: يتم ضبطه فور نجاح is_owner() وقبل تشغيل أدوات المالك.

3) صفحة المالك كانت تعرض رسالة Network/RLS عامة.
   الإصلاح: إضافة Probe حقيقي إلى /auth/v1/health مع Timeout وتصنيف config / DNS-network / key / Auth / RLS.

4) لوحة المالك كانت تنتظر تحميل بقية الجداول قبل إطلاق noor:admin-ready.
   الإصلاح: فتح لوحة المالك وإطلاق الحدث فور نجاح صلاحية Owner، ثم تحميل الجداول الثانوية بعد ذلك.

5) ملف التثبيت V81_01 كان يحتوي CREATE POLICY غير قابل لإعادة التشغيل.
   الإصلاح: إضافة DROP POLICY IF EXISTS قبل كل Policy.

6) grant service_role كان يأتي قبل إنشاء جداول V81 المتأخرة.
   الإصلاح: إضافة grant نهائي بعد إنشاء كل جداول V81، وإنشاء Migration آمن للقاعدة الحالية.

7) Manifest/PWA كان ما زال V69 ويستخدم start_url/scope = / غير مناسب لـ GitHub Pages داخل /noor-aldhikr/.
   الإصلاح: start_url/id/scope أصبحت ./ والاختصارات أصبحت نسبية.

8) bootstrap.js كان يسجل sw.js?v=69.0.0.
   الإصلاح: إصدار Service Worker أصبح مأخوذًا من NOOR_CONFIG.appVersion.

9) أرقام النسخة ونصوص صفحة المالك كانت قديمة (V65/V50/V43).
   الإصلاح: تحديث الواجهة ولوحة المالك إلى V81.7 وإزالة تعليمات V43/V49/V50 القديمة.

10) سياسة الخصوصية كانت تصف AI مدفوع/Edge Function قديم.
    الإصلاح: تحديثها لتصف FREE AI الحالي.

11) مسارات قديمة داخل v40-17 وv40-19 كانت لا تزال تستدعي Edge Function noor-ai/OpenAI.
    الإصلاح: تحويلها لاستخدام FREE AI المحلي وقاعدة معرفة Supabase فقط.

12) عند تعذر Supabase في الصفحة العامة، تسجيل الدخول كان يمكن أن يحجب الموقع كله.
    الإصلاح: المحتوى العام يظل متاحًا وتظهر رسالة واضحة أن المزايا السحابية متوقفة مؤقتًا.
